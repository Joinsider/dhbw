# Phase 07.1: iOS FileViewer Errors - Context

**Gathered:** 2026-04-01
**Status:** Ready for planning
**Source:** Urgent insertion after Phase 7

## Problem Statement

The iOS fileviewer implementation has missing expect/actual implementations for macOS platform variants:
- `macosArm64Main` (Apple Silicon macOS)
- `macosX64Main` (Intel macOS)

The fileviewer uses KMP expect/actual pattern for platform-specific file operations. Currently, implementations exist for:
- `commonMain` (expect declarations)
- `androidMain` (Android implementation)
- `desktopMain` (generic Desktop/JVM implementation - used for Windows/Linux)
- `iosMain` (iOS implementation)

But the macOS-specific variants are missing, causing IDE errors on builds targeting macOS.

## Boundary

This phase fixes IDE compilation errors by providing macOS-specific expect/actual implementations for the fileviewer functions:
- `openFile(byteArray, fileName)` — Open/view a file (platform-native)
- `saveFileWithDialog(byteArray, fileName)` — Save file with user dialog

## Decisions

### iOS/macOS Architecture
- iOS and macOS share the same implementation because both use Apple/Darwin platform
- Use `iosMain` source set implementation as the base for macOS
- Both should use native iOS/macOS APIs (UIDocumentInteractionController, UIActivityViewController, etc.)

### Desktop/macOS Architecture
- Desktop (JVM) needs its own implementation separate from iOS
- Desktop implementation should work for both `desktopMain`, `macosX64Main`, and `macosArm64Main`
- Use Java/Swing APIs for file operations (Desktop.getDesktop().open(), FileChooser, etc.)

### Implementation Strategy
1. Move common iOS/macOS implementation to `iosMain` (already exists)
2. Create `macosMain` source set for shared iOS+macOS code (Kotlin Multiplatform standard pattern)
3. OR: Create separate `macosX64Main` and `macosArm64Main` that delegate to Desktop implementations
4. Update `build.gradle.kts` to include macOS source sets in Kotlin multiplatform configuration

### the agent's Discretion
- Exact mechanism for sharing code between iOS and macOS (shared `macosMain` vs separate implementations)
- Which file APIs to use on macOS (native Swift interop vs Java)
- Error handling strategy for file operations
