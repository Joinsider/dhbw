## Technical Notes

### Platform-Specific API Choices

**macOS (Native Target):**
- Uses AppKit for native macOS UX (`NSWorkspace`, `NSSavePanel`)
- Uses Foundation for data handling (`NSData`, `NSTemporaryDirectory`)
- Provides platform-native file dialogs and workflows

**Why Not UIKit (iOS APIs)?**
- UIKit is iOS-specific; macOS uses AppKit for native applications
- NSWorkspace and NSSavePanel are the macOS-idiomatic way to handle file operations

**Why Not Desktop/JVM Approach?**
- Desktop/JVM implementation uses Java Swing (`java.awt.FileDialog`, `java.awt.Desktop`)
- Native macOS targets compile to native code (via Kotlin Native), not to JVM
- Must use Swift interop with Foundation/AppKit frameworks

### Kotlin Native Interop Notes

- Uses `@OptIn(ExperimentalForeignApi::class)` for `kotlinx.cinterop` features
- Uses `usePinned` + `addressOf` for safe ByteArray-to-NSData conversion
- Uses `platform.Foundation.*` and `platform.AppKit.*` for Framework bindings
